## Priority Issues

- **[P2-1] The keyboard highlight in menus and the command palette is nearly invisible** (newly noticed: unchanged code).
  - What: `.or-menu__item` sets `outline: none` (`packages/ui/styles/actions.css:303`) and shows the highlighted item only by a background: `[data-highlighted] { background: var(--or-hover) }` (`actions.css:352`) on the menu's `--or-raised`. Dark: `#15111f` on `#17131f`, 1.02:1 (the highlight is darker than the menu). Light: `#ece8ef` on `#f5f3ee`, 1.09:1. The danger item uses `--or-fail-tint` the same way (`actions.css:366`). The palette's `.or-palette__option[aria-selected="true"] { background: var(--or-sel) }` (`surfaces.css:762`) is 1.09:1 dark, 1.25:1 light.
  - Why: a keyboard user can't see which item Enter will activate (every ⋯ menu, the pin menu, the org switcher, the command palette).
  - Not caught because no capture opens a menu with an item highlighted, and the keyboard walk checks only that focus styles differ, not that they're visible.
  - Fix: one visible highlight in `@omniralph/ui` for menu items and palette options (e.g. an inset `outline: 2px solid var(--or-acc); outline-offset: -2px` like `.or-row-link:focus-visible::after` at `lists.css:171`, or a highlight with ≥ 3:1 against `--or-raised` / `--or-surf`), in both themes. Add a capture step that opens a ⋯ menu and arrows to an item (and the palette with a result selected).
  - Serves: WCAG 2.4.7 Focus Visible, 1.4.11 Non-text Contrast. Routes: `fleet-agent-menu`, `repo-agents-menu`, any palette route.
- **[P2-2] On phone, the routing "Default" badge is clipped to "D"** (newly noticed: unchanged code).
  - What: under "After each repo's work item match", each built-in rule shows a lone "D" box on a second line (`settings-advanced-routing.phone.dark`, `member-settings-advanced-routing.phone.light`, behind the sheet in `settings-advanced-routing-edit.phone.*`). At ≤768 px `.or-routing__rule` becomes `grid-template-columns: 24px minmax(0, 1fr)` (`apps/web/src/screens/settings/routing/routing.css:104-111`); the default row's third child, `<MetaBadge text="Default" />` (`routing-rules-settings.tsx:520`), wraps into the 24 px column. User rules don't break because `.or-routing__actions` is pinned to `grid-column: 2`.
  - Why: the badge's meaning is lost and the row looks broken; "D" reads like a size badge.
  - Fix: in the 768 px query place the default row's badge in column 2 (`justify-self: start`), or keep a third `auto` column for `.or-routing__rule--default`.
  - Serves: rule 1, rule 16, WCAG 1.3.1. Routes: `settings-advanced-routing`, `member-settings-advanced-routing`, `settings-advanced-routing-edit` at phone, both themes.
