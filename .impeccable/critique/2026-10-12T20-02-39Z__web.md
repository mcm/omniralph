## Design Specificity Verdict

**LLM assessment:** The panel is about half authored for this product. What is Omniralph's own:
- the centralised state vocabulary;
- mono identifiers in the "Flight Recorder" voice;
- consequence copy ("A harness is online while its last heartbeat is less than 60 seconds old");
- the Waiting alert that names the blocking manual story.

What any admin template would have:
- every page is a 48px H1, a muted subtitle and a stack of same-weight cards;
- analytics is the stock "four KPI tiles plus area chart plus bar chart";
- nothing is staged around "what happened, why, and is it getting better": `/` redirects to Repositories, and a run reads as six equal cards instead of one log.

**Deterministic scan:** On `src`, one finding (`broken-image`, a test fixture, false positive). On the snapshots, 2170 findings: 2124 primary and 46 advisory.
- **Real:**
  - low-contrast (88);
  - skipped-heading (156, from `CardTitle`/`AlertTitle` defaulting to h3/h5 after the page h1: 99 + 20 uses with no `as`);
  - undersized-ui-text (132, the 10px header avatar initials at `app-header.tsx:152`, below DESIGN.md's 11px floor).
- **False positives, recorded in `.impeccable/critique/ignore.md`:** marquee, radial-halo (library CSS), overused-font (sanctioned Geist Mono), cramped-padding (unresolved Tailwind v4 spacing), tight-leading (library typography), nested-cards (icon tile), em-dash-overuse (content and placeholders).
- **What the detector caught that the design review only suspected:** the 0.7-opacity dimming of dismissed findings and disabled rules, and raw `--glacier-300` text colour.
- **Where the design review went further:** it caught the phone breakage that the overflow check misses.

**Visual overlays:** none. No browser on the host, so nothing was injected. The snapshot scans stand in for it.

## Overall Impression

Calm, correct and well worded at 1440px, but structured like a generic admin panel. It breaks at 390px. The biggest opportunity is to make each screen answer its question first: what failed and what to do now, what a setting change will affect, and the status of every row on a phone.

## What's Working

1. **One state vocabulary, really centralised.** `src/lib/state-variants.ts` drives every state badge and the analytics series.
2. **Consequence copy.** "Disconnecting keeps a repository's review history", "Lowering a limit doesn't cancel running jobs", "Effective now: 2." This is configuration safety at the copy level.
3. **Guarded, specific destructive actions and an audit trail.** "Stop the run of FIX-100?" offers "Keep running". Finding dismiss and restore show who did it, how and when.

## Priority Issues

**[P1] 1. Phone layouts break: shell header, page headers, analytics grids, list key columns**
- **Why it matters:** PRODUCT says a run or review can be checked at 390px. Today status is off-screen in every list and the header covers content.
- **Evidence:**
  - Header has a fixed `height:52` and wrapping breadcrumbs (`app-header.tsx:307-322`).
  - Header rows don't wrap and use `flexShrink:0` actions (`repositories-view.tsx:510-536`, `review-detail-view.tsx:222,264`).
  - Fixed `repeat(4,…)` and `2fr 1fr` grids (`analytics-view.tsx:219,246,328,463,490,530,620`).
  - Screenshots: `repositories.phone.dark`, `review.phone.dark`, `repositories-gitlab.phone.light`, `analytics.phone.light`, `ralph.phone.light`, `reviews.phone.light`, `jobs.phone.dark`.
- **Fix:**
  - Header: `min-height`, truncate the breadcrumbs, hide the user name below 768px.
  - A shared `PageHeader` whose actions wrap.
  - Auto-fit analytics grids.
  - Below 640px, list rows stack as identifier, status, then time.
- **Command:** /impeccable adapt

**[P1] 2. Run-affecting settings save without confirmation, defaults or diff**
- **Why it matters:** This violates PRODUCT principle 1 and DESIGN's "settings as forms with consequences".
- **Evidence:**
  - Repository settings: 5 cards under one save (`repository-settings-view.tsx:493`).
  - Ralph settings: 7 cards under one save (`ralph-settings-section.tsx:584-589`).
  - Profiles change every repository that uses them (`profiles-view.tsx:62,170`).
  - No dirty state anywhere in `src`.
- **Fix:**
  - One save per card, with Discard/Save shown when the card is dirty.
  - State the default in each `Field` description.
  - For run-affecting cards, confirm with a list of what changes. For profiles, list the affected repositories.
- **Command:** /impeccable harden

**[P1] 3. Run detail buries the answer, and a failed run gives no next step**

**[P1] 6. Text fails WCAG AA in both themes (FR-7)**
- **Evidence:**
  - Dismissed or resolved findings and disabled rules are dimmed with `opacity:0.7`. That puts tertiary and secondary text and badges at 2.8–3.5:1 and also dims working Restore/Edit/Delete controls (`review-detail-view.tsx:102`, `rules-view.tsx:321`). Routes `review`, `repository-rules`.

  - The auth monogram is 2.3:1 on its gradient in dark (`auth-shell.tsx:61-66`).
  - Marginal: a secondary button's `--accent` text on `--bg-raised` at 4.34:1 (`onboarding-view.tsx:205-214`). An info badge on the raised selected profile card at 4.16:1 (`profile-facts.tsx:62` via `repository-settings-view.tsx:288`).
- **Fix:**
  - Mark inactive items with a badge or muted heading, not opacity on content.
  - Use semantic text tokens (`--text-accent`, `--text-secondary`).

  - Don't put accent text or tinted badges on raised backgrounds.
